Lock files & SBOMs for OS package managers

Record a machine.
Rebuild it anywhere.

matsya snapshots every installed package into a reviewable lock file, replays it on other machines, catches drift, and turns it into CycloneDX or SPDX SBOMs. One static binary, no dependencies.

Install

One command on Linux, macOS and Termux. No root required.

$ curl -fsSL https://raw.githubusercontent.com/dmdhrumilmistry/matsya/main/install.sh | sh

Checks the SHA-256 before installing. Options and details

$ cargo install matsya

Builds from crates.io.

$ gh attestation verify matsya-x86_64-linux -R dmdhrumilmistry/matsya

Download a binary from the latest release, then verify its build provenance. All platforms

$ matsya lock                  # snapshot this machine
$ matsya sbom -o sbom.cdx.json # CycloneDX SBOM
$ matsya check                 # exit 1 on drift
$ sudo matsya apply            # rebuild elsewhere

Quick start guide

  • No root needed. Uses sudo or doas only if the target directory isn't writable, otherwise installs to ~/.local/bin.
  • Termux ready. On Android it installs the native build into $PREFIX/bin.
  • Verifiable. Every release binary ships with a SHA-256 file and a GitHub build attestation.

How it works

Four commands cover the whole life of a machine.

  1. matsya lock

    Reads the package databases and writes a sorted, deterministic matsya.lock.json.

  2. matsya check

    Compares the live system with the lock and exits 1 on drift. Made for CI and cron.

  3. matsya apply

    Installs the exact locked versions with the native package manager, in one transaction.

  4. matsya sbom

    Turns the lock into CycloneDX 1.6 or SPDX 2.3, without touching the machine.

$ matsya check
environment: ubuntu-24.04-x86_64
[apt] 1 extra, 2 changed
  + cowsay 3.03+dfsg2-8build1  (installed, not locked)
  ~ jq 1.8.1-4ubuntu2 -> 1.8.1-4ubuntu1
matsya: drift detected

Drift shows up as plain, reviewable lines. See the command reference for every flag.

Why matsya

Language ecosystems have had lock files for years. The operating system underneath usually gets a hand-written apt-get install line and hope.

Real lock files

Exact version, architecture, install reason, holds, dependencies, repository and signing key, plus the SHA-256 from signed repo metadata.

One file, many machines

Your Mac, the CI runner, the Raspberry Pi and your phone live side by side as environments in one lock.

Vanished versions still install

Falls back to snapshot.debian.org, snapshot.ubuntu.com, Fedora Koji, the Arch Linux Archive or brew extract, and checks the hash first.

Reproducible SBOMs

purls with distro qualifiers, license expressions, hashes and the dependency graph, ready for Grype, Trivy or OSV.

Reviewable diffs

Sorted JSON. Re-locking an unchanged machine leaves the file alone, so git diff shows exactly what moved.

Depends on nothing

A ~3 MB static binary with its own database readers and HTTPS client. Lock, check and SBOM work with an empty PATH.

Beyond the package manager

A machine is more than its distro packages. matsya records the tools you installed by other means too, in the same lock and SBOM, read straight from disk.

Language tools

pip and pipx, npm -g, cargo install, go install and gem, system-wide or per user. apply reinstalls the exact versions.

App stores

snap revisions and flatpak apps pinned to their deployed commit, for the whole system or one user.

Everything else

Binaries dropped into /usr/local/bin or /opt (by SHA-256) and macOS apps outside Homebrew, including the App Store. check tells you when one changes.

Why "matsya"?

In the Matsya Purana, Vishnu takes the form of Matsya, a horned golden fish, and warns the sage Manu of a great flood. Manu fills a boat with the seeds of every plant, every kind of creature and the Vedas. Matsya tows it safely through the deluge, and the world is rebuilt from exactly what was saved.

That is the job: record everything a machine is made of, carry it safely, and rebuild the same world somewhere else.
